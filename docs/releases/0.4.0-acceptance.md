## Automated qualification

The 2026-09-01 candidate passes the following checks:

- `bun install --frozen-lockfile`
- `bun run generate-routes`
- `bun run fmt:check`
- `bun run lint`
- `bun run typecheck`
- `bun test`
- `bun run build`
- `bunx wrangler d1 migrations apply DB --local --persist-to tmp/d1-0.4.0-qualification` against an empty local D1 state
- development startup against the migrated local D1 state with a successful `GET /login`
- `git diff --check`

The clean migration applies migrations 0000 through 0004. Migration 0004 adds the immutable Security activity table and indexes; application startup does not perform schema migration.

The Bun suite uses the real Better Auth handler with `Request` objects and clean Miniflare D1 databases for direct Admin Plugin authorization, Standard Account target guards, Ban and Unban state transitions, Session revocation, OAuth credential cleanup, retained Application Authorizations, retryable partial cleanup, best-effort Security activity writes, and sensitive-data redaction. Application-owned projections are exercised against the same migrated schema for Accounts, safe Sessions, global/per-Account Security activity, deterministic pagination and filters, and Dashboard metrics.

Existing OAuth 2.1/OIDC, OAuth Client creator ownership, owner-scoped Management activity, Application Authorization, Password Reset, GitHub, and operations-only Administrator role policy tests remain in the full suite. Automated tests use deterministic email/CAPTCHA substitutes and do not call Resend, GitHub, Turnstile, public relying parties, or other production services.

## Residual risk

Easy Auth remains development-stage and does not claim production readiness, compliance-grade auditing, high availability, monitoring, disaster recovery, deployment automation, browser-E2E automation, or security certification.

Security activity is immutable and retained permanently, but it is best-effort operational history rather than an atomic audit log. A successful Better Auth security mutation remains successful if the later Security activity insert fails; the sanitized failure is logged, and no durable outbox or automatic retry closes that gap. Direct D1 Administrator assignment remains operations-only and outside application activity history. Already delivered ID tokens and relying-party local sessions cannot be recalled by Easy Auth.
