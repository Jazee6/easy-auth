# Easy Auth 0.2.0 acceptance

## Automated qualification

The release candidate is qualified with:

```bash
bun run fmt:check
bun run lint
bun run typecheck
bun test
bun run build
git diff --check
bunx wrangler d1 migrations apply DB --local --persist-to /tmp/easy-auth-0.2.0-d1
```

The clean temporary D1 migration pass applies `0000`, `0001`, and `0002`, including database-backed rate limiting and the partial unique index that permits at most one GitHub identity per user.

Automatic tests use an injected email sender and application policy seams. They do not call Resend, GitHub, or production Turnstile and do not add browser E2E infrastructure.

## Manual external-service acceptance

A maintainer must configure the bindings in `README.md` and complete the manual acceptance scenarios in `.scratch/easy-auth-0.2.0/spec.md` before deployment. This pass requires real development Resend and GitHub OAuth credentials and a manually selected Turnstile key pair, so it is not performed by the automated qualification run.

Residual risk until that pass is recorded: provider-dashboard callback configuration, real email delivery, GitHub profile/email responses, OAuth cancellation behavior, managed-widget rendering, and responsive browser interaction remain externally dependent and manually verified only.
