# Easy Auth 0.3.0 acceptance

Status: automated qualification complete; manual reference-client acceptance pending

## Automated qualification

The 2026-08-28 candidate passes the following checks:

- `bun run generate-routes`
- `bun run fmt:check`
- `bun run lint`
- `bun run typecheck`
- `bun test`
- `bun run build`
- `bunx wrangler d1 migrations apply DB --local --persist-to tmp/d1-test` against an empty local D1 state
- `git diff --check`

The clean migration applied migrations 0000 through 0003, including Admin, JWT, OAuth Provider, D1 rate-limit, and OAuth client audit state. The Bun suite exercises real `Request` objects through `auth.handler` against a clean temporary Miniflare D1 database. It covers consent denial, first acceptance, reuse, narrower scopes, expansion, Authorization Code with S256 PKCE, signed ID-token JWKS verification, UserInfo, introspection, refresh rotation, revocation, client-lifecycle rollback and cleanup, direct-consent rejection, and ban cleanup. Exact command output belongs to the release commit or CI log rather than this document.

## Residual risk

This release does not claim production readiness, high availability, monitoring, disaster recovery, deployment automation, browser-E2E automation, or security certification. Direct D1 role assignment and OAuth client ownership transfer are deliberately outside the application audit trail. Already delivered ID tokens and relying-party local sessions cannot be recalled by Easy Auth.
